## Scope and interface

The new private `parseSPL2Document(text string) *spl2ParsedDocument` owns a dedicated `spl2.IQueryContext`, `antlr.CommonTokenStream`, unchanged `sourceIndex`, diagnostics, `syntaxComplete`, `semanticComplete`, and normalized syntax facts. `semanticComplete` remains false in every intermediate parse. No public selector, Analyze dispatch, command lowering, source-map implementation, shared transfer, legacy parser or runtime dependency changed.

`parser/spl2` is generated exclusively from the new separate lexer/parser grammars. The lexer has call-local brace nesting and quote-mode returns. String, quoted name, raw string, interpolation, slash-regex and embedded-text classes remain distinct. Rex uses its own lexer mode, so `a/b/c` cannot become a slash regex. Nested interpolation contains ordinary generated expression contexts, including nested quotes, object/array expressions and their exact original locations. Syntax facts carry grammar-owned `kind`, terminal `value`, canonical `location`, and recursive `children`. Their test-only normalized `shape()` collapses routing rules, preserving operators and branching constructs. Later lowering should consume the generated contexts rather than parse fact strings.

The admitted Task2 shells are FROM dataset, minimal SELECT expressions FROM dataset, explicit/index-first search, makeresults, eval assignments, pipe where, fields/table lists, minimal rex and embedded-command wrappers. Completing command/SQL options belongs to subsequent tasks. There is no generic balanced-token fallback establishing supported syntax conformance. Wildcard consumption exists only in explicitly rejected module/declaration/statement-suffix contexts. Unsupported future command grammar is not advertised through the public analyzer.

Expressions have explicit arithmetic/unary/comparison/predicate/Boolean precedence and distinct search precedence. Search RHS values are owned by `searchValue`, unlike expression access reads. Calls allow ordinary positional `=` comparisons, all-named colon arguments, and positional prefixes followed by named suffixes; array-valued named lists have their own array context. Named labels, object keys and lambda parameters/locals have distinct grammar ownership. Typed/default and signed-constant lambda parameters, expression/block bodies, newline/semicolon assignment separators and final return are covered. Nested lambdas produce a located contract finding. Duplicate decoded object keys produce a located contract-invalid `SPL_SYNTAX_ERROR` diagnostic while retaining complete grammar coverage; nested objects have independent key sets.

H05 trailing array commas, EH04 IS NOT type, and H12 slash regex containing an internal pipe are recognized as incomplete without error-severity findings. All 17 H/EH records remain held in provenance without floor credit. Expression-position search literals and command embeddings have distinct outer contexts but their inner body coverage remains explicitly incomplete; no wrapper-only completeness claim is made. Full embedded/body modeling remains later work.
