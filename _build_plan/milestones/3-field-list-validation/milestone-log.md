## What's new in the app

- Validate query fields against an offline list or an object catalog with optional declarations and identity/version metadata.
- Follow derived fields, exact nested names, removals, and supported wildcard projections through canonical query flow, with located outcomes and per-match evidence.
- Validate one Query Document or an ordered batch from Go, CLI, native Python, or REST with identical report values.
- Distinguish valid, invalid, and incomplete results without hiding trustworthy findings or coverage gaps.

## Implemented decisions

Catalog names are case-sensitive and exact, including nested names. A parent declaration does not imply its leaves. Derived names need no catalog declaration. Optionality is declaration-only: `optional_equivalent` is valid but establishes neither event presence nor structural/query availability. Catalog metadata is descriptive and causes no file/network resolution. Empty catalogs are valid; empty batches are errors.

The finite source universe refines supported wildcard expansion and downstream lineage inside the Go kernel. Outcomes retain all matches with their concrete name, source/derived binding, and individual ordinary/optional result. Harmless exclusions do not create source obligations; conclusive empty inclusions are missing. Removed fields remain unavailable. The validator consumes kernel evidence instead of replaying query transfers.

All reports have integer schema_version 1. Invalid takes precedence over incomplete, then valid; coverage gaps remain visible even with a definite error. Original text and source IDs are preserved, locations use half-open UTF-8 byte ranges and Unicode code-point columns, and arrays remain arrays. Batch order is input order and malformed batch requests return no partial reports. Content invalid/incomplete reports are emitted with CLI exits 1/3 and HTTP 200; usage/options/I/O failures use CLI exit 2 and rejected API requests use HTTP 400.
