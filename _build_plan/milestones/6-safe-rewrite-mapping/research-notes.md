## Controller-approved design decisions

- Conditions use conservative three-valued guaranteed source/flow facts. AND combines compatible facts, OR intersects guarantees, query NOT establishes no positive equality, and independent child queries cannot authorize parent edits. Later facts do not authorize earlier edits. False and unknown are distinct and neither means absent event data.
- Source mappings preserve explicitly created aliases and outputs. Canonical implicit-output changes require atomic linked edits. Rule order is not precedence, identical edits coalesce, and conflicting targets/overlaps/static capture remain ambiguous. Collision checks cover observed canonical bindings rather than requiring proof that unreferenced event fields do not exist.
- Post-analysis must preserve intended mapped static binding/lineage relationships, not merely parse successfully. Apply has a whole-request verification gate, retains original returned text on failure and marks every proposed edit not committed. Existing unrelated incomplete semantics can remain without optional validation; explicitly requested destination validation must be conclusive and error-free.
- The new strict versioned request is separate from legacy mapping configuration. Conditions support all/any, proven scalar equality/string contains and source-reference-present; no regex, caller-injected context or condition-language NOT. Logical field atoms and navigation paths remain distinguishable. Preview is default; apply returns text/report data and never edits query files in place.
- Go, CLI, actual native Python and REST expose canonical single/batch results for both dialects. Audit retains original and candidate locations, proposed versus committed distinctions, ordinary explained false/unmatched skips and incomplete ambiguous/unknown outcomes. Actual internal hooks and the final plan wait for verified M5.
