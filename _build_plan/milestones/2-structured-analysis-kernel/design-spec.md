# Milestone 2: Structured Analysis Kernel

## Purpose and approved scope

SPL Toolkit gains a canonical, deterministic description of a query that explains references, stage order, nested scopes, field availability and lineage, exact source locations, and limits of its understanding. The existing flat discovery and mapping interfaces remain compatible. Go, CLI, native Python, and REST expose equivalent new analysis results. This milestone implements no external field-list or schema validation, broad SPL2 parsing, new rewrite semantics, batch scanning, graph presentation, SARIF, or editor service.

The delegated product decision maker approved the additive kernel, source contract, flow semantics, and adapter/testing design on 2026-09-07. This spec implements the milestone 2 scope of `_build_plan/prd.md`. Temporary build-plan artifacts are never runtime dependencies.

## Architecture and alternatives

The chosen architecture adds public `pkg/analysis`, using an additional analysis entry rule in the existing ANTLR grammar and command-specific processing of its parse-tree contexts. Existing grammar entry points and legacy mapper listener contracts stay available. Necessary lexer additions and generated parser changes require baseline regressions. Where analysis expression lexing needs a different boundary from legacy mapping, an immutable per-input CharStream marker enables that narrow ANTLR lexer predicate; unmarked legacy inputs retain original tokenization. No global switch or post-lex token rewriting is allowed, and sequential/concurrent mixed-mode tests must prove isolation. No regex, string-splitting parser, or token-text heuristic substitutes for grammatical structure. Matching a parsed command name to its semantic handler is legitimate; guessing expression structure from its text is not.

Replacing legacy discovery immediately would reduce duplicate paths but break baseline classifications and ABI expectations. Adding scope fields to the old flat result would preserve appearance at the cost of an inadequate model. The additive approach gives later milestones a stable dependency while preserving established callers.

A parse-tree listener records stages, expressions, nested scopes, and references using typed ANTLR contexts. Separate command transfer functions calculate each stage's effect on available fields. Recovery retains trustworthy contexts around damaged input. Public types never expose generated parser contexts or tokens. All mutable parser and analysis state is per call; published capabilities are copied before returning to a caller.

## Document and report contract

`analysis.Analyze(document QueryDocument) (*Result, error)` is the canonical entry point. `analysis.Capabilities() CapabilityManifest` reports coverage. A Query Document contains JSON keys `text`, `language`, `profile`, `version`, and `source_id`. Empty option values normalize to `spl`, `splunkd`, and `current`; `source_id` defaults to an empty string. Text and source identity are retained byte-for-byte. Invalid UTF-8 text or source identity is a document error; REST/C adapters reject malformed raw UTF-8 before JSON decoding can replace bytes. `version` means the selected compatibility contract, not the machine-report format. Here `current` means the SPL subset declared by this build's capability manifest, not a promise to match an unpinned Splunk server. Any nonempty language other than `spl`, profile other than `splunkd`, or version other than `current` returns a documented invalid-document error; adapters reject that request consistently. Whitespace-only or malformed query text produces a structured syntax-invalid result, not an API error.

The result JSON has `schema_version` equal to the integer `1`, normalized `document`, `status`, `coverage`, `stages`, `scopes`, `references`, `lineage`, `dependencies`, and `diagnostics`. `status` is `valid`, `invalid`, or `incomplete`. A definite syntax or unavailable-field error wins and makes status invalid even if another stage is incomplete. Without definite errors, any uncovered syntax or semantics makes status incomplete. Valid means this analysis is complete and error-free; it says nothing about field existence in an external schema or search runtime success.

Coverage has booleans `syntax_complete`, `semantic_complete`, and ordered distinct diagnostic-code `reasons`. Successful grammar recognition alone never establishes semantic completeness. Recoverable syntax errors make syntax and semantic coverage false. Definite unavailable reads can retain semantic completeness because their effects are understood.

Every collection is an array, including when empty, and is serialized as `[]`, never `null`. IDs use deterministic source-order counters (`scope-0`, `stage-0`, `ref-0`); query traversal is preorder, so a parent's owning stage precedes child stages. Stage `position` is zero-based within its own scope. References are ordered by source start, then source end, kind, role, and stable traversal sequence; IDs are assigned in that final order. Dependency arrays are unique and lexically sorted. Diagnostics sort by source start, then stable code, then message. Field-state fields sort by exact normalized name. Repeated and concurrent identical calls produce equal JSON values.

## Source, references, and lineage

A `location` is a half-open range with `start` and `end` positions. Each position has `offset` (zero-based UTF-8 byte offset), `line` (one-based), and `column` (one-based Unicode code-point column). End-of-input positions are legal. Convert ANTLR rune indexes to byte offsets explicitly; do not slice Go strings using rune indexes. CRLF advances one line, and tabs count as one code point. Stage spans exclude an introducing pipeline separator and include the command and arguments. Scope spans include brackets for child scopes; the root spans the entire original text.

A reference's `original_name` is exactly the text covered by its location, including quote delimiters when present. `normalized_name` removes identifier/value quoting and escaping according to the grammar but preserves field and dependency case. Command and function names are normalized lowercase. Each reference has `id`, `kind`, `role`, `stage_id`, `scope_id`, `location`, `resolution`, `binding`, and `origin_reference_ids`. Kinds are `field`, `index`, `source`, `sourcetype`, `dataset`, `lookup`, `data_model`, and `macro`. Roles are `read`, `create`, `rename`, `remove`, `filter`, `group`, `sort`, and `output`. Resolution is `exact`, `wildcard`, or `dynamic`. It follows the parsed semantic role: quoted expression identifiers may be exact, while search-value patterns and wildcard projection selectors retain pattern semantics even when quoted; quote presence alone is never the classifier. Unproven selector forms remain incomplete. Field read binding is `source`, `derived`, `unavailable`, or `indeterminate`; conditional derived fields are indeterminate unless the operation proves availability. Creation and non-field references use `not_applicable` binding. Origin IDs connect a derived read to creating references and preserve chains through renames.

A stage contains `id`, lowercase `command` (synthetic `search` for implicit search and `macro` for a typed macro-only stage), `position`, `scope_id`, `location`, and `semantic_complete`. A scope contains `id`, `parent_id`, `kind`, `stage_id`, and `location`; root parent/owner IDs are empty. Kinds are `root`, `subsearch`, `join`, `append`, and `appendpipe`.

A lineage entry belongs to one stage and scope and contains `before`, `after`, and ordered `transitions`. A field state contains known `fields` (name, origin reference IDs, conditional flag), `removed` names, `open`, and `uncertain`. Open means other source fields may exist, not that any external schema confirms them. Closed means a projection/aggregation constrained output names. Uncertain means an unmodeled stage might alter those facts. A transition contains `operation`, `output`, `input_reference_ids`, `output_reference_id`, and `conditional`; operations are `create`, `rename`, `remove`, `aggregate`, `lookup`, and `project`. Dependencies contain arrays `indexes`, `sources`, `source_types`, `datasets`, `lookups`, `data_models`, and `macros`. A qualified data-model source exposes the root model and qualified dataset separately. In a single qualified operand their reference spans overlap (root component versus full dataset); in `datamodel Web All_Traffic search`, the dataset reference covers original All_Traffic but normalizes to Web.All_Traffic. This bounded normalization occurs only inside grammar-established dependency operands. A statically named macro dependency has exact resolution even while its unexpanded semantics remain incomplete.

## Grammar, coverage, and partial findings

The new entry rule understands pipelines, optional initial search, comparisons, AND/OR/NOT, parenthesized expressions, arithmetic and concatenation, comma-separated assignments, function arguments, IN lists, quoted identifiers and strings, command field lists, wildcard field forms, macro invocations, and bracketed subqueries. Named grammar contexts distinguish assignment targets from expression reads, function names from arguments, search literals from expression fields, command options from event fields, and lookup catalog columns from local event fields. Existing legacy query contexts remain intact.

The full semantic set is search, where, eval, rename, fields, table, stats, eventstats, streamstats, lookup, inputlookup, sort, dedup, head, and tail in explicitly supported forms. Baseline dependency constructs for datamodel/from/tstats and macros receive grammatical dependency identification, but unimplemented field effects remain incomplete. Joins and append branches expose child stages and dependencies without promising complete merge semantics. Other parsed commands are opaque stages with `SPL_UNSUPPORTED_COMMAND` or `SPL_UNSUPPORTED_SEMANTICS` diagnostics. Their field effects introduce uncertainty. Preserve a dependency inside an opaque context only if a grammar rule establishes its kind.

The capability manifest has `schema_version: 1`, `language`, `profile`, `version`, `commands`, and `functions`. Entries have `name`, `syntax_supported`, `semantic_supported`, and `limitations`. Every modeled command/function is listed. Grammar-accepted but unmodeled commands are listed with semantic support false. An unknown command remains incomplete and never inherits a default complete handler. Common pure argument-reading functions include abs, round, ceil/ceiling, floor, len, lower, upper, trim/ltrim/rtrim, substr, replace, coalesce, if, case, isnull/isnotnull, tonumber, tostring, mvcount, split, and match. Aggregate support includes count, sum, avg, min, max, values, list, dc/distinct_count, first, and last. Function-specific arity/form restrictions are checked. Unknown functions and dynamic field/query semantics, such as unresolved macro expansion, searchmatch, or computed identifier arguments, report incomplete instead of interpreting strings as ordinary fields. The final manifest documents exactly the tested forms.

ANTLR recovery is retained, with command-boundary synchronization if default recovery consumes later intact stages. Synchronization follows parsed/tokenized brackets, parentheses, and pipelines; never split original strings on a pipe. Error listeners include lexer errors. References depending on inserted or damaged parse nodes are withheld; intact references elsewhere survive. For `search host=web | eval broken= | stats count by user`, retain the host and user reads, plus a syntax diagnostic at the damaged assignment. A later otherwise correct stage cannot erase the earlier error. Unresolved macros produce macro dependencies and incomplete semantics while preserving surrounding discoveries.

## Field transfer rules

Search predicates treat bare right-hand values as literals (`host=web` reads host only). Expression comparisons in where and eval treat identifiers on either side as reads (`where src=dest` reads both). Index/source/sourcetype selectors create dependency references for their values rather than source-required event fields. Field names are case-sensitive even though command and function matching is case-insensitive.

Eval processes assignments left-to-right. In `eval a=src, b=a+1`, src is a source read, a is derived before b reads it, and b points through a to src. Self-assignment reads the prior binding before replacing it. Rename resolves every source against the environment before the command, then removes old names and installs destinations; overlapping source/destination chains, swaps, duplicate sources/destinations, and collisions are incomplete rather than guessed. Before-state resolution applies to ordinary distinct non-overlapping renames and is not evidence of unverified overlap evaluation. Exact removals record tombstones. Table closes the field set. Fields inclusion preserves known internal bindings and tombstones, with exact closure when its input was already closed. With open input, unknown retained-internal membership yields explicit incomplete coverage rather than invented _raw/_time bindings or false unavailable reads; later finite-catalog refinement belongs to milestone 3. Fields exclusion preserves openness while recording exact removals. Wildcards operate on provably known fields but unresolved membership produces incomplete coverage and retains wildcard references.

Stats outputs only aggregate outputs and grouping keys, closing projection. Eventstats and streamstats add aggregate outputs while retaining input fields; unsupported options such as wildcard expansion or window-dependent constructs remain incomplete if they change modeled effects. An aggregate without AS gets its SPL output name (`count` or the semantic name such as `sum(bytes)`, with canonical function case and insignificant whitespace removed while preserving field case) and a located output reference covering the original function call. If an implicit output name cannot be proven, that form is incomplete. Lookups read local input fields and create outputs; aliased catalog columns are not event-field reads. OUTPUTNEW creates conditional lineage and must not overwrite an already-known binding. Inputlookup records its dependency and produces an open source environment; no catalog columns are invented.

Sort and dedup read parsed field lists; head/tail preserve fields for supported numeric forms. A reference to a removed field, or to an absent name in a known closed projection, emits `SPL_UNAVAILABLE_FIELD` and invalid status. A later unknown-effect stage removes the ability to prove such absence, so reads become indeterminate without fabricated invalid errors. Structural field availability is separate from external schema existence.

Ordinary subsearches, join, and append child searches use independent environments, so a child's derived name cannot suppress a parent's source read. Appendpipe inherits a copy of the parent environment. Child outputs never leak directly back into parent state. Join/append/appendpipe merging produces uncertainty unless a specific implemented transfer proves the resulting availability; the milestone may leave merges incomplete while still exposing the child lineage.

## Diagnostics and failure behavior

Diagnostics contain `code`, `severity`, `category`, `message`, `location`, `stage_id`, and `scope_id`. Initial stable codes are `SPL_SYNTAX_ERROR` (error/syntax), `SPL_UNAVAILABLE_FIELD` (error/unavailable_field), `SPL_UNSUPPORTED_COMMAND` (warning/unsupported_semantics), `SPL_UNSUPPORTED_SEMANTICS` (warning/unsupported_semantics), `SPL_UNSUPPORTED_FUNCTION` (warning/unsupported_semantics), `SPL_DYNAMIC_REFERENCE` (warning/unsupported_semantics), and `SPL_UNRESOLVED_WILDCARD` (warning/unsupported_semantics). Messages identify the construct and limitation. Request-option failures are transport/API errors outside this report, never hidden query diagnostics. A panic or internal failure is not silently converted into a valid or empty report.

## Public adapters and compatibility

The CLI adds `analyze` with existing `--query`/positional query, `--format text|json`, and `--output` behavior, plus `--language`, `--profile`, `--compatibility-version`, and `--source-id`. `capabilities` supports text/JSON and output. Analysis returns status exit codes 0 valid, 1 invalid, 3 incomplete, 2 usage/I/O/options errors. It writes the report before returning the content status. Existing commands and exit behavior are unchanged. JSON is the direct canonical report; text presents status, coverage, references and their locations, and diagnostics.

Python adds `SPLMapper.analyze_query(query, *, language='spl', profile='splunkd', version='current', source_id='') -> dict` and `SPLMapper.capabilities() -> dict`. C exports `spl_mapper_analyze_query(handle, document_json)` and `spl_mapper_capabilities(handle)` returning the existing owned SPLResult structure. Python uses the current operation guard and always calls `spl_result_free` in a finally block after decoding. Invalid options raise SPLMapperError; query invalid/incomplete outcomes return the dict. Closed handles behave consistently with existing methods.

REST adds `POST /api/v1/query/analyze` accepting the QueryDocument directly and `GET /api/v1/capabilities`. HTTP 200 contains the direct report for all query statuses; malformed JSON/unsupported document options return 400 using existing transport errors. Existing request body limits and middleware apply. API documentation includes both routes. No adapter contains field classification or transfer logic.

Legacy `DiscoverQuery`, Python QueryInfo, discover CLI, REST discover, and mapping remain available. Documentation directs structured consumers to Analyze and explains why legacy flat InputFields cannot describe flow or completeness. All analysis package sources are included in Python source distributions and native builds.

## Verification and acceptance

A shared corpus under `testdata/analysis/` covers comparisons and literals, nested function arguments, sequential assignments, case preservation, Unicode before/inside quoted identifiers, exact removals, closed projection/aggregation, lookup aliases/OUTPUTNEW, independent and inherited scopes, every dependency kind, wildcard/dynamic forms, unknown commands/functions, partial syntax recovery, and invalid-plus-incomplete precedence. Assertions include positive references and negative cases (function names, literals and lookup catalog columns must not appear as input event fields).

Go tests assert flow and source slices, deterministic JSON, repeated/concurrent analysis, and no public parser internals. Shared acceptance compares full canonical report values from Go, CLI, actual native Python, and REST; normalization is limited to JSON object-key order. Original text, source ID, collection order, diagnostic messages, and locations must match. Capability values must also agree. Existing Go race and real-library Python suites continue passing. Native packaging includes the kernel in a source-built wheel. Generated grammar changes are reproducible with ANTLR 4.13.2 and retain all legacy tests. Local checks do not claim cross-platform release-matrix acceptance.
